The "Kup konsultację online" / "Buy an online consultation" / "Online-Beratung kaufen" button on the environmental consulting pages posts to `/api/create-checkout-session`. That endpoint creates a Stripe Checkout Session and redirects the visitor to the Stripe-hosted payment page.

Until `STRIPE_SECRET_KEY` and `STRIPE_CONSULT_PRICE_ID` are set, the button sends visitors to the contact form on the same page instead of failing.

## Values to Replace

The following values are placeholders and must be updated before going live.

**Files containing placeholders:**
- [server/checkout.js](server/checkout.js)

| Field | Current Value | What to Set |
|-------|--------------|-------------|
| mode | payment | Keep `payment` for a one-off paid consultation. Use `subscription` only if you sell a recurring plan. With `subscription`, also add `payment_method_collection: "always"`. |
| success_url | `${DOMAIN}/doradztwo-srodowiskowe?platnosc=ok&session_id={CHECKOUT_SESSION_ID}` (EN `/environmental-consulting`, DE `/umweltberatung`) | Change it only if you want a separate thank-you page. Keep the `{CHECKOUT_SESSION_ID}` template. The page shows a thank-you note when `platnosc=ok` is present. |
| cancel_url | `${DOMAIN}/doradztwo-srodowiskowe` (per language) | Change it only if cancelled payments should return somewhere else. |
| line_items[].price | `process.env.STRIPE_CONSULT_PRICE_ID` (not set yet) | The Price ID (`price_...`) of the consultation product. Create it at https://dashboard.stripe.com/prices, e.g. "Konsultacja środowiskowa – 1 h". |

## Setup

1. In the Render service **otoneso** go to **Environment** and add:
   - `STRIPE_SECRET_KEY`: a secret key from https://dashboard.stripe.com/test/apikeys (`sk_test_...` for testing, `sk_live_...` for production). Do not commit it to the repo.
   - `STRIPE_CONSULT_PRICE_ID`: the `price_...` ID of the consultation.
   - `DOMAIN` (optional): defaults to `https://otoneso.com`.
2. Save. Render redeploys the service.
3. The publishable key is not needed, because the button redirects to the Stripe-hosted page.

## Project structure

- `server/checkout.js`: Express endpoint `POST /api/create-checkout-session`. Listens on 127.0.0.1:4242 inside the container.
- `server/package.json`, `server/package-lock.json`: dependencies (`stripe` 23.0.1, `express` 5.1.0).
- `nginx.conf.template`: `/api/` is proxied to the Node endpoint. Everything else is still served by nginx as before.
- `Dockerfile`: installs Node, installs the server dependencies and starts `checkout.js` next to nginx.
- The pay button and the thank-you note live in the consulting pages, which are generated by the site generator.

## How it works

1. A visitor clicks the pay button. The form posts `lang` (pl, en or de) to `/api/create-checkout-session`.
2. The server creates a Checkout Session with the parameters above and redirects to `session.url`.
3. The visitor pays on the Stripe-hosted page.
4. Stripe returns them to `success_url`, where the page shows a thank-you note. If they cancel, Stripe returns them to `cancel_url`.
